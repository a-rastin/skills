# General Conversion Rules

## Output scope

Default output is a body fragment, not a complete document. Generate a full document only when explicitly requested.

## Paragraphs and line breaks

- A blank line in the input represents a paragraph break.
- Preserve paragraph breaks as blank lines in LaTeX.
- Join hard-wrapped lines that clearly belong to the same paragraph with one space.
- Do not use `\\` to separate ordinary paragraphs.
- Preserve intentional line breaks only in structures where line breaks are semantically required, such as poetry, addresses, tabular rows, or explicitly requested layouts.
- `@onepar` overrides ordinary paragraph boundaries as defined in the command reference.

## Text-mode reserved characters

Escape literal reserved characters in ordinary text as follows:

| Input | LaTeX output |
|---|---|
| `#` | `\#` |
| `$` | `\$` unless it delimits valid explicit mathematics |
| `%` | `\%` unless `@percent` replaces it with `درصد` |
| `&` | `\&` |
| `_` | `\_` unless used inside valid math mode |
| `{` | `\{` |
| `}` | `\}` |
| `~` | `\textasciitilde{}` unless it is existing intentional LaTeX syntax |
| `^` | `\textasciicircum{}` unless used inside valid math mode |
| `\` | `\textbackslash{}` unless it belongs to valid LaTeX intentionally preserved from input or generated by the converter |

### Escaping safeguards

- Never double-escape syntax generated by the converter.
- Escape only the textual content inside command arguments; keep generated braces and backslashes active.
- Do not escape ampersands that the converter intentionally creates inside a math alignment or table.
- Preserve existing valid LaTeX only when it is clearly supplied as intentional code. Otherwise treat backslashes as literal text.

## Whitespace

- Collapse multiple ordinary spaces to one in prose.
- Preserve non-breaking relationships only when semantically necessary.
- Do not replace Persian zero-width non-joiners with spaces.
- Do not insert manual `\hspace` or `\vspace` unless explicitly requested.

## Emphasis

- Explicit bold → `\textbf{...}`.
- Explicit emphasis/italic → `\emph{...}` by default.
- Preserve nested emphasis with balanced commands.
- Do not infer emphasis from quotation marks, capitalization, or position.

## Headings

Convert only explicit Markdown-style headings:

```text
# Main heading
## Subheading
### Lower heading
```

into:

```latex
\section{Main heading}
\subsection{Subheading}
\subsubsection{Lower heading}
```

Do not use `\chapter` unless the user explicitly marks or requests a chapter, because the parent document class may not support it.

## Lists

Use list environments only when requested by `@itemize` or `@enumerate`, unless the user explicitly asks for list conversion in natural language.

- Each `\item` contains one source item.
- Join continuation lines into the preceding item.
- Preserve nested lists only when indentation or markers clearly show nesting.
- Keep environment nesting valid.
- Do not retain source bullet or number markers after creating `\item`.

## Quotations

- Preserve Persian guillemets `«...»` as supplied.
- Preserve Unicode curly English quotation marks as supplied.
- Straight quotation marks may remain literal unless the user requests typographic TeX quotes.
- Do not turn ordinary quoted text into a `quote` environment without explicit block-quote structure or instruction.

## Dashes and ranges

- Preserve Unicode en dashes and em dashes.
- Do not transform a hyphen inside a compound word, identifier, negative number, or filename.
- Convert a clearly marked textual range written with an en dash as supplied; do not invent range endpoints.

## Mathematics

### Explicit math

Preserve valid explicit delimiters:

- Inline: `\(...\)` or `$...$`
- Display: `\[...\]`
- Numbered: `\begin{equation}...\end{equation}`
- Multiline: standard `amsmath` environments when already present or explicitly required

### Conservative conversion

- Convert a plain expression to math mode only when it is unmistakably mathematical.
- Do not treat monetary dollar signs as math delimiters.
- Do not treat underscores in filenames, usernames, or identifiers as subscripts unless the context is mathematical.
- Use braces for all superscripts and subscripts.
- Use `\text{...}` for normal-language words inside math only when `amsmath` can reasonably be assumed from explicit math context.
- Do not derive missing sides, variables, units, operators, or results.
- Do not change decimal separators or digit scripts.

### Examples

```text
The value of x is 5.
```

```latex
The value of $x$ is 5.
```

This conversion is allowed only if `x` is clearly a mathematical variable. When uncertain, preserve it as text.

```text
y = mx + c
```

```latex
\[
y = mx + c
\]
```

Use display math only when the expression is a standalone mathematical line.

## Citations and references

- Preserve `[1]`, `(Smith, 2024)`, DOI text, and other supplied citation text.
- Never invent a BibTeX key.
- Convert to `\cite{key}` only when the exact key is explicitly supplied and the user requests citation-command conversion.
- Do not invent `\label` or `\ref` targets.

## URLs, emails, paths, and code-like text

- Preserve content exactly.
- Escape reserved characters if leaving it as plain text.
- Do not automatically introduce `\url`, `\href`, `\path`, `\verb`, or `listings` because package availability is unknown.
- In Persian text, a coherent URL, email, file path, command, or English code-like span may be wrapped in `\lr{...}` after its internal LaTeX characters are safely handled.

## Existing LaTeX in otherwise plain input

When input mixes plain text with deliberate LaTeX:

1. Preserve clearly valid LaTeX commands and environments.
2. Convert surrounding plain text.
3. Do not modify command names or arguments unless the user explicitly requests it.
4. Validate brace and environment balance.
5. If intent is ambiguous, prefer treating the sequence as literal text rather than executing unknown LaTeX.

## No-content-loss audit

Before output, compare input content with output conceptually:

- Recognized command tokens may disappear.
- Source list markers and source numbering may disappear when replaced by environments.
- Markdown emphasis markers may disappear when replaced by LaTeX commands.
- All substantive text must remain.
